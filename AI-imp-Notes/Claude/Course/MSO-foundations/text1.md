## Claude Developer Certification Notes
### How LLMs Behave: Tokens, Context Window, Sampling, and Non-Determinism

---

### 1. Tokens: The Unit of Input, Output, and Cost

#### What Are Tokens?

Tokens are the small pieces of text that Claude actually processes.

The model does **not** read text as humans do. Instead, it converts text into tokens before processing it.

##### Example

Text:

```text
Hello, how are you today?
```

Possible tokenization:

```text
["Hello", ",", " how", " are", " you", " today", "?"]
```

> The exact tokenization depends on the model and tokenizer being used.

---

#### Why Tokens Matter

Everything sent to or generated by Claude consumes tokens:

- System prompt
- User prompt
- Conversation history
- Documents
- Tool definitions
- Tool outputs
- Model response

---

#### Example Token Usage

```text
User Prompt      = 500 tokens
Conversation     = 2,000 tokens
Document         = 5,000 tokens
Response         = 1,000 tokens
```

Total:

```text
500 + 2,000 + 5,000 + 1,000
= 8,500 tokens
```

These 8,500 tokens count toward:

- Context window usage
- API cost

---

#### Key Takeaway

✅ Think in **tokens**, not words.

##### Certification Tip

> Cost and context limits are measured in tokens.

---

### 2. Context Window: The Model's Working Memory

#### What Is a Context Window?

The context window is the maximum number of tokens Claude can process in a single request.

Think of it as the model's working memory.

##### Analogy

Imagine a desk that can hold 100 books.

If 100 books are already on the desk, book #101 cannot be added unless something is removed.

Claude works the same way.

---

#### What Occupies the Context Window?

```text
System Prompt
+
Conversation History
+
Documents
+
Tool Outputs
+
Response Being Generated
```

Everything must fit within the window.

---

#### Context Window Failure Modes

##### Case 1: Input Exceeds the Window

```text
Context Window = 200K tokens
Input = 250K tokens
```

Result:

```text
Validation Error
```

The request is rejected before generation begins.

---

##### Case 2: Output Exceeds the Window During Generation

```text
Context Window = 200K tokens
Input = 190K tokens
```

Eventually:

```text
190K + Output > 200K
```

Result:

```text
Generation Stops
```

You receive a partial response.

---

#### Real-World Impact

##### During Development

```text
Short conversations
Small datasets
Limited tool usage
```

Everything works fine.

##### In Production

```text
Long conversations
Large documents
Multiple tool calls
```

The context window fills much faster.

---

#### Common Solutions

Applications typically:

- Trim old messages
- Summarize conversation history
- Remove unnecessary context
- Use retrieval instead of sending entire documents

---

#### Key Takeaway

✅ The context window is a fixed token budget.

##### Certification Tip

> Input and output share the same context window budget.

### 3. Sampling: Why Responses Vary

#### What Is Sampling?

A language model does not always choose the single most likely next token.

Instead, it calculates probabilities for possible next tokens and samples from that distribution.

---

#### Example

Prompt:

```text
What is the capital of France?
```

Possible probabilities:

```text
Paris   = 98%
London  = 1%
Lyon    = 1%
```

Claude then samples from this distribution.

Result:

```text
Paris
```

---

#### Temperature

Temperature controls randomness in sampling.

---

##### Low Temperature (0.0 - 0.2)

Characteristics:

- More focused
- More predictable
- More consistent
- More repeatable

Example:

```text
Explain recursion.
```

Responses tend to be similar across runs.

---

##### High Temperature (0.8 - 1.0+)

Characteristics:

- More creative
- More diverse
- Less predictable
- More variation

```text
Write a fantasy story.
```
